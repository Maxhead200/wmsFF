# ФОТ: исправление смен и первоначальные тарифы

Кандидат из `fix/payroll-shift-photo` в `feature/wb-print-check`. Ещё не опубликован.

Форма редактирования открывается поверх табеля. Приход и уход сохраняют точность
исходных отметок, если администратор меняет только обед. Ручной обед задаётся один
раз на дату начала смены и распределяется пропорционально между ставками. Пустое
поле возвращает автоматический вычет, ноль отменяет вычет. Отмена смены сохраняет
исходную запись и аудит, исключает её из табеля, пересечений и состояния планшета.
Оплаченные дни защищены; права филиала проверяются сервером.

Новая карточка позволяет сразу задать HOURLY или PIECE, отдельно PALLET для
грузчика, с датой начала действия. Сотрудник и ставки создаются атомарно.
Предыдущие ставки не подставляются в новую карточку.

Фото: сравнение четырёх полученных файлов с хешами исходных отметок показало
совпадение. Два ранних файла уже тёмные, два последних светлые. Причина отличия
от изображения, которое пользователь видит на планшете, ещё не установлена.
В просмотре добавлена подпись сотрудника/отметки, прежнее изображение скрывается
до загрузки нового. Захват камеры в APK не изменён.

## Проверка

- Автоматические тесты обеда: воспроизведение отказа до исправления, затем зелёные.
- PostgreSQL: обед на несколько выходов, отмена, повтор отмены, права филиала,
  защита оплаченного дня, отсутствие восстановления отменённого прихода при
  повторной доставке события, создание сотрудника со ставками.
- Браузер на тестовых данных: открытие/сохранение редактора, обед 30 минут,
  удаление смены, новый сотрудник со ставками 350 ₽/час и 500 ₽/паллету,
  чистые тарифы при открытии следующей карточки.
- API: 2899 passed / 94 skipped. Отдельный `kiz-duplicate.integration.spec.ts`
  исключён: его специальная БД не настроена. Web: 257 passed. TypeScript API/web.

## Публикация

Изменения только в модуле ФОТ/планшетов, за действующими флагами нашей WMS.
Проданную WMS не публиковать. Миграция `20260927192000_payroll_shift_corrections`
добавляет nullable `PayrollShift.cancelledAt` и таблицу `PayrollWorkDay`.
Для кандидата нужен Prisma Client, сгенерированный с новой схемой. Сначала
проверить свежие image ID и baseline; глобальная source parity остаётся false.
Материализовать runtime и накладывать только проверенные модули, не весь dist.
Старый API совместим с добавленной схемой; при откате после появления отменённых
смен он не учитывает `cancelledAt`, поэтому отмены нужно учесть отдельно до отката.
Миграция и изменения пользовательских данных в production ещё не выполнялись.
